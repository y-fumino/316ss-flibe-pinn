# flibe-pinn — A Two-Axis Diagnostic for Molten-Salt Corrosion

Code, data, and complete result ledgers for:

> Y. Fumino, *A Two-Axis Diagnostic for Molten-Salt Corrosion: Mass Deficit and
> Diffusion Regime via a Self-Auditing Inversion*, submitted to the Journal of
> Nuclear Materials (2026).

The paper establishes a two-axis diagnostic for published corrosion data: a
model-free mass deficit Δ (computed from a depth profile and a gravimetric
record before any model is invoked) and a transport-regime shape index α
(recovered by a self-auditing physics-informed inversion). This repository
regenerates every number, table, and figure in the paper from the released
code, and reproduces the archived result ledgers bit-for-bit under the pinned
environment.

## Try it on your own data (no training required)

```
python tools/delta_from_csv.py --profile your_profile.csv --mass-loss 0.724 --density 8.86 --c-bulk 7.53
```

Two routine measurements — a digitized depth profile (CSV: `depth_um, C_wt_pct`)
and a gravimetric mass loss — are enough to run **Step 0** of the diagnostic.
Arithmetic only: no model, no training, no fitting.

What it reports:

- the **depletion budget** ρ(C_bulk − C_surface)L/100 over the measured extent,
  and how much of it the measured loss occupies — the ceiling on what any
  profile shape could ever explain;
- the model-free deficit **Δ** under the analysis-convention grid, and the
  **regime** that follows (deficit / sign-unstable / intermediate);
- the two decisions that regime implies: whether the domain must be reduced
  before inverting, and **which inversion module to run** —
  `pinn_production_coupled` when Δ is not positive (a closed balance, or a
  negative systematics residual of the 316SS type — paper Section 3.3), and
  `pinn_eds_only` when it is (a coupled run would then spend the deficit as a
  boundary lift and fail the audit).

What it does **not** do:

- it does not size a reduced domain. When Δ says the balance cannot close, the
  reduced domain is set from the SEM-observed intragranular depletion depth
  (paper Section 3.3, ≈2.5× that depth) — an input this tool does not have.
  Pass `--domain-um` once you have sized it to see the grid on that domain;
- it does not write an alloy configuration. The profile arrays, gravimetric
  record, temperature, and outlier rule go into `src/alloy_configs.py` by hand.

Units: `--mass-loss` in **mg/cm²** (not mdd or mg/dm²), `--density` in **g/cm³**,
depths in **µm**, concentrations in **wt%**. `--c-bulk` is the certified
composition; without it the nominal baseline falls back to the plateau mean and
the baseline axis of the convention grid is not exercised (the tool says so).
`--c-surface` defaults to the outermost profile point.

## Environment

Two reproducibility levels are supported and documented in the paper's Data
Availability statement:

1. **Bit-identical** under the pinned environment (`requirements.txt`,
   float64, CPU): re-running any campaign batch reproduces the archived
   ledger bit-for-bit, down to optimizer step counts. Verified for every
   production configuration.
2. **Conclusion-identical** across environments (signs, audit pattern,
   solution families, values within reported spread): verified on Linux and
   Japanese-locale Windows.

```
pip install -r requirements.txt
```

## Reproducing the campaign (one road)

```
python tools/check_ledger.py            # expects: ledger complete: 25 files (results/bootstrap/ is checked by content, not by seal)
python tools/test_delta_regression.py   # standalone Delta tool: Table S19 values and Step 0 regimes
# data-origin uncertainty (Table S16; Table 2 note); --alpha-reference is always explicit,
# never the resample median (self-referential near zero):
python tools/bootstrap_uncertainty.py --alloy 316SS --mode coupled --n 50 --alpha-reference -0.339 --sigma 1.25
python tools/bootstrap_uncertainty.py --alloy HASTN --mode eds --n 25 --alpha-reference -0.640
python tools/bootstrap_uncertainty.py --alloy 316H --mode eds --n 25 --alpha-reference +0.707
# to re-verify a batch bit-for-bit, set the released ledgers aside first:
#   copy results/ to results_reference/   (any means; it is the comparison reference)
python src/run_all.py --batch N1        # or N2 … N11; resume-capable
python tools/compare_ledgers.py results_reference/<file>.json results/<file>.json
```

`compare_ledgers` prints `BIT-IDENTICAL` when every numeric field matches
exactly; the released `results/` directory is the reference the paper quotes.
`campaigns.json` is declarative: each batch lists its jobs, seeds, and
overrides, with a comment stating what the batch establishes.

Batches are ordered to follow the paper: the production ensembles first
(N1–N3, Sections 4.1–4.3), the protocol-robustness axes next (N4–N5), then
the supplementary validations in section order (N6–N10 ↔ Sections S3–S6,
with N9/N10 following the order of Tables S10–S14); N11 is the 316SS anchor-free
control that completes the symmetric design (§3.4, Table S18).

| Batch | Establishes | Paper |

| N1 | 316SS coupled production ensemble | §4.1; Tables 2–4, S1 |
| N2 | Hastelloy-N production (coupled + EDS-only) | §4.2; Tables S2, S4 |
| N3 | 316H production (coupled + EDS-only + α₀ control) | §4.3; Tables S3, S5–S6 |
| N4 | weight insensitivity, consistent regime (w_mass 20/30/40) | §4.3 |
| N5 | deficit-regime variants: violation conservation under weight and anchor form | §4.3–4.4; Fig. 5 |
| N6 | single-anchor validation | Section S3 |
| N7 | synthetic verification: sign integrity and audit response under injected deficits | Section S4; Tables S7–S9 |
| N8 | domain-size and outlier characteristics | Section S5 |

## Ledger field dictionary

Each `results/*.json` file is one configuration: a header (protocol string,
run tag, overrides, seeds run) and a `seeds` list. Per seed:

- `D0`, `alpha`, `D_wall` — fitted parameters (cm²/s; α dimensionless).
- `loss`, `eds_rmse`, `eds_nrmse` — fit quality.
- `mass_rmse`, `mass_ratio` — **fit-side mass diagnostics. Read with care:**
  for coupled runs on deficit alloys the optimizer is forced toward the
  anchor, so `mass_ratio ≈ 1` does *not* mean the profile supports the mass;
  for EDS-only runs `mass_ratio` is an unfitted prediction against the raw
  replicate records (mean of per-replicate ratios). The paper's deficit
  quantity is *not* this field: it is the audited field integral ∫(1−u)dx
  against the gravimetrically constrained value (Section 4.4 states the
  convention). **The field’s definition also differs by module generation**:
  the linear modules record the mean over the gravimetric anchors of the
  pointwise predicted/measured loss (Table 3’s 1.03 for 316SS), while the
  quadratic-closure modules (N9–N10) record the final-time ratio
  w(1,t₁)/w_target (0.92 for 316SS; Table 3 note). The ledgers are archived
  as-run and are not rewritten.
- `lbfgs_steps`, `retries`, `converged` — optimizer bookkeeping (part of the
  bit-identity surface).
- `audit` — the conservation audit: `w_pred_at_x1_t1`, `integral_1_minus_u`,
  `w_gap`, `w_pred_at_x0_t1`, `w_target`, `u_min/max_on_grid`, `audit_pass`.
  The signed violation total w(0,1) + w_gap — algebraically w(1,1) − ∫(1−u)dx, the unmet remainder — is the conserved quantity of Section 4.3.

## Applying the framework to a new alloy

Two edits: add one configuration dictionary to `src/alloy_configs.py`
(profile arrays, gravimetric record, constants — data only; written by hand), and
one job line to `campaigns.json`. Everything else — protocol, audit, tables,
figures — follows unchanged. Step 0 of Section 5.6 applies first:
`tools/delta_from_csv.py` decides, from the profile and the balance record alone,
whether Δ is not positive — full measured extent, module `pinn_production_coupled` —
or a convention-invariant deficit prescribes domain reduction (sized from the
SEM-observed depletion depth) and module `pinn_eds_only`. The tool reports these
two decisions; it does not generate the configuration.

Note that the coupled and anchor-free inversions are **separate modules**, not
a weight setting: `pinn_eds_only` omits the mass anchor entirely (a 7-component
loss vector against the coupled 8), so `w_mass = 0` on the coupled module is
not equivalent to it.

## Data provenance

`data/*.csv` are our digitizations (WebPlotDigitizer) of figures in the
published source studies, which are cited in the paper; they are provided for
reproducibility with full attribution. No original corrosion experiments were
conducted.
